# การคำนวณ {#solving}

```ts
solver.solve()
```

`solve()` กำหนดหมายเลขสมการ ประกอบเมทริกซ์ความแข็งรวมและเวกเตอร์แรงกระทำของทุกกรณีแรงกระทำ แล้วแก้หาการกระจัดและแรงปฏิกิริยา หลังจากนั้นจึงอ่าน [ผลลัพธ์](/th/solver/results) ได้ทุกค่า ถ้าอ่านก่อนจะได้ `TypeError` ขั้นตอนเหล่านี้คือขั้นตอนเดียวกับในหน้า [EduBeam คำนวณโมเดลอย่างไร](/th/elements/analysis) ของคู่มือทฤษฎี

ผลลัพธ์แม่นตรงสำหรับโมเดลเชิงเส้น รูปร่างที่เสียรูปและแรงภายในตลอดชิ้นส่วนแต่ละชิ้นมาจากสูตรปิดของคาน Timoshenko จึงไม่มีโครงข่ายเอลิเมนต์ (mesh) ที่ต้องปรับให้ละเอียด และไม่ต้องแบ่งชิ้นส่วนย่อยเพื่อให้แผนภาพแม่นยำ

ตั้งแต่เวอร์ชัน 0.3.1 `solve()` ไม่เขียนอะไรลง console ส่วนเวอร์ชัน 0.3.0 พิมพ์บรรทัดอย่าง `Solution took 9 [ms]` ทุกครั้งที่เรียก

## คำนวณใหม่หลังแก้ไขโมเดล {#solving-again-after-a-change}

การเปลี่ยนตัวเลขในโมเดลต้องการเพียง `solve()` อีกครั้ง แต่ถ้าชุดสมการเปลี่ยน ต้องเพิ่มอีกหนึ่งบรรทัดก่อน:

```ts
domain.createNode('C', [10, 0, 0], [DofID.Dz])
domain.createBeam2D(2, ['B', 'C'], 1, 1)
solver.codeNumberGenerated = false // DOF เปลี่ยน: กำหนดหมายเลขใหม่
solver.solve()
```

| การแก้ไข | จากนั้น |
| --- | --- |
| ค่าของแรงกระทำ แรงกระทำที่เพิ่มหรือลบ | `solve()` |
| พิกัดโหนด วัสดุ หน้าตัด จุดหมุน | `solve()` |
| เพิ่มโหนดหรือชิ้นส่วน | `codeNumberGenerated = false` แล้ว `solve()` |
| ลบโหนดหรือชิ้นส่วน: `domain.nodes.delete(label)`, `domain.elements.delete(label)` | `codeNumberGenerated = false` แล้ว `solve()` |
| เปลี่ยนจุดรองรับของโหนด `node.bcs` | `codeNumberGenerated = false` แล้ว `solve()` |

ถ้าลืมหลังเพิ่มโหนด `solve()` จะ throw `TypeError` ถ้าลืมหลังเปลี่ยนจุดรองรับ ตัวคำนวณจะคำนวณด้วยจุดรองรับเดิม **โดยไม่แจ้งเตือน** ถ้าไม่แน่ใจ ให้ตั้งค่านี้ใหม่ไว้ก่อน การกำหนดหมายเลขแทบไม่เสียเวลาเลย การลบชิ้นส่วนยังหมายถึงต้องลบแรงกระทำของชิ้นส่วนนั้นออกจาก `lc.elementLoadList` ด้วย ไม่เช่นนั้น `solve()` จะ throw `RangeError` เพราะหาชิ้นส่วนไม่พบ

ถ้าต้องการคำนวณโมเดลเดียวกันหลายรูปแบบ เช่น ศึกษาผลของการเปลี่ยนพารามิเตอร์ การสร้างตัวคำนวณใหม่สำหรับแต่ละแบบง่ายกว่าและเร็วพอ ๆ กัน ดู [ตัวอย่างเส้นอิทธิพล](/th/solver/scripts#an-influence-line-as-csv)

## เมื่อคำนวณไม่สำเร็จ {#when-solving-fails}

โครงสร้างที่เคลื่อนที่ได้โดยไม่เสียรูป ซึ่งก็คือกลไก มีเมทริกซ์ความแข็งเอกฐาน (singular) บางครั้ง `solve()` ตรวจพบและ throw error:

```text
Error: Linear system cannot be solved since matrix is singular
```

แต่หลายครั้งตรวจไม่พบ ความคลาดเคลื่อนจากการปัดเศษทำให้เมทริกซ์ดูเหมือนแก้ได้ แล้วคุณจะได้การกระจัดขนาด $10^{12}$ m หรือตัวเลขที่ดูสมเหตุสมผลสำหรับโครงสร้างที่เลื่อนไปได้อย่างอิสระ ตัวอย่างเช่น คานบนจุดรองรับแบบล้อเลื่อนสองจุดคำนวณได้โดยไม่มีข้อความเตือน ตราบที่ไม่มีแรงผลักในแนวนอน จึงควรตรวจจุดรองรับด้วยตัวเอง และถือว่าการกระจัดขนาดมหาศาลเป็นสัญญาณของกลไก

สาเหตุที่พบบ่อย:

- จุดรองรับน้อยเกินไป เช่น คานบนจุดรองรับแบบล้อเลื่อนสองจุด
- จุดรองรับที่ยึดโครงสร้างไว้ไม่ได้ เช่น ขนานกันทั้งหมด หรือชี้เข้าหาจุดเดียวกันทั้งหมด
- จุดหมุนเกินมาหนึ่งจุด เช่น จุดหมุนสามจุดเรียงกันบนแนวเดียว
- โมเมนต์ที่กระทำที่จุดต่อซึ่งปลายของทุกชิ้นส่วนเป็นจุดหมุน

ข้อความ error ไม่บอกว่าปัญหาอยู่ที่ใด แอป EduBeam ตรวจหากลไกก่อนคำนวณ แล้วแสดงภาพเคลื่อนไหวว่าโครงสร้างเคลื่อนที่อย่างไร การสร้างโมเดลเดียวกันในแอปจึงมักเป็นวิธีที่เร็วที่สุดในการเห็นปัญหา หน้า [การแก้ปัญหา](/th/reference/troubleshooting) รวบรวมสาเหตุที่พบบ่อย

ถ้าขาดโหนด วัสดุ หรือหน้าตัด จะเกิด `RangeError` ที่ระบุชื่อ แต่ถ้าขาดพารามิเตอร์ของหน้าตัดจะไม่มี error เลย ผลลัพธ์ทุกค่าเป็น `NaN` ดู [วัสดุและหน้าตัด](/th/solver/materials-sections#cross-section)

## ขนาดโมเดล {#model-size}

ตัวคำนวณใช้เมทริกซ์แบบเต็ม (dense) ซึ่งเหมาะกับโมเดลขนาดที่ใช้ในการสอน บนแล็ปท็อปใน Node ชิ้นส่วนที่เรียงต่อกันเป็นเส้นตรงใช้เวลาคำนวณประมาณ:

| ชิ้นส่วน | DOF | เวลา |
| --- | --- | --- |
| 50 | 150 | 0.1 s |
| 100 | 300 | 0.2 s |
| 200 | 600 | 1 s |
| 400 | 1200 | 10 s |

ทุกครั้งที่โมเดลใหญ่ขึ้นสองเท่า เวลาจะเพิ่มขึ้นหกถึงเก้าเท่า

โจทย์ โครงข้อแข็ง และโครงถักทุกข้อในวิชาการวิเคราะห์โครงสร้างคำนวณได้สบาย แต่ไลบรารีนี้ไม่ได้ออกแบบมาสำหรับโมเดลที่มีชิ้นส่วนหลายพันชิ้น

## ไม่มีการวิเคราะห์แบบอื่น {#no-other-analyses}

เวอร์ชันนี้คำนวณได้เฉพาะการวิเคราะห์สถิตเชิงเส้น ซอร์สโค้ดมีตัวคำนวณค่าลักษณะเฉพาะ (eigenvalue) สำหรับความถี่ธรรมชาติ แต่ไม่ได้อยู่ในแพ็กเกจที่เผยแพร่ `EigenValueDynamicSolver` จึง import จาก `@edubeam/fem` ไม่ได้
