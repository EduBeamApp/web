# โหนดและจุดรองรับ {#nodes-and-supports}

โหนดคือจุดที่ชิ้นส่วนเชื่อมต่อกัน จุดรองรับไม่ใช่ออบเจกต์แยก แต่เป็นรายการองศาความเป็นอิสระที่โหนดยึดไว้ โค้ดสั้น ๆ ในหน้านี้เป็นส่วนหนึ่งของโปรแกรมแบบเดียวกับในหน้า [เริ่มต้นใช้งาน](/th/solver/getting-started) และใช้ `solver`, `domain` และ `lc` ของโปรแกรมนั้น

## สร้างโหนด {#create-a-node}

```ts
domain.createNode(label, [x, y, z], bcs)
```

| อาร์กิวเมนต์ | ชนิด | ความหมาย |
| --- | --- | --- |
| `label` | `string \| number` | ชื่อของโหนด เก็บเป็นสตริง: `1` กับ `'1'` คือโหนดเดียวกัน |
| `coords` | `number[]` | `[x, y, z]` หน่วยเมตร โดย `y = 0` แกน z ชี้ลง |
| `bcs` | `DofID[]` | องศาความเป็นอิสระที่จุดรองรับยึดไว้ ไม่ต้องใส่ถ้าเป็นโหนดอิสระ |

เมธอดคืนค่าเป็น `Node` และหาโหนดนี้อีกครั้งได้ด้วย `domain.getNode(label)` ถ้าใช้ชื่อที่มีอยู่แล้ว โหนดใหม่จะแทนที่โหนดเดิม

```ts
import { DofID } from '@edubeam/fem'

const fixed = [DofID.Dx, DofID.Dz, DofID.Ry]
domain.createNode('A', [0, 0, 0], fixed)
domain.createNode('B', [0, 0, -4]) // อิสระ: ยอดเสาสูง 4 m
```

## จุดรองรับ {#supports}

จุดรองรับแต่ละแบบในแอป EduBeam คือชุดของ DOF ที่ยึดไว้:

| จุดรองรับ | `bcs` | ยึด |
| --- | --- | --- |
| ยึดแน่น | `[DofID.Dx, DofID.Dz, DofID.Ry]` | ทุกองศา |
| หมุด | `[DofID.Dx, DofID.Dz]` | การกระจัดทั้งสองทิศ หมุนได้อิสระ |
| ล้อเลื่อน | `[DofID.Dz]` | การกระจัดแนวดิ่ง กลิ้งตามแกน x |
| ล้อเลื่อนแนวตั้ง | `[DofID.Dx]` | การกระจัดแนวนอน กลิ้งตามแกน z |
| แบบเลื่อน | `[DofID.Dz, DofID.Ry]` | การกระจัดแนวดิ่งและการหมุน เลื่อนตามแกน x |
| แบบเลื่อนแนวตั้ง | `[DofID.Dx, DofID.Ry]` | การกระจัดแนวนอนและการหมุน เลื่อนตามแกน z |
| ยึดการหมุนเท่านั้น | `[DofID.Ry]` | การหมุน |

ลำดับที่คุณระบุคือลำดับที่ [แรงปฏิกิริยา](/th/solver/results#reactions) คืนกลับมา โครงสร้างต้องมี DOF ที่ยึดไว้อย่างน้อยสามองศา และต้องจัดวางให้โครงสร้างเคลื่อนที่เป็นกลไกไม่ได้ ดู [เมื่อคำนวณไม่สำเร็จ](/th/solver/solving#when-solving-fails)

DOF ที่ยึดไว้ยังกำหนดให้เคลื่อนที่ไปตามระยะที่ต้องการได้ด้วย ซึ่งก็คือการทรุดตัวของจุดรองรับ ดู [การกระจัดที่กำหนด](/th/solver/temperature-settlements#prescribed-displacements)

## จุดรองรับแบบเอียง {#inclined-supports}

ล้อเลื่อนบนพื้นเอียงยึดโหนดในทิศตั้งฉากกับพื้นเอียง ไม่ใช่ในแนวดิ่ง ให้หมุนแกนของโหนดด้วย `updateLcs` แล้ว `bcs` ของโหนดจะอ้างถึงแกนที่หมุนแล้ว ในโปรแกรมของหน้าเริ่มต้นใช้งาน ให้สร้าง B แบบนี้แทน:

```ts
const b = domain.createNode('B', [6, 0, 0], [DofID.Dz]) // ยึดแกน z ของโหนดเอง
const a = (30 * Math.PI) / 180 // 30° จาก x ไปทาง z: ตามเข็มนาฬิกาบนหน้าจอ
b.updateLcs({ locx: [Math.cos(a), 0, Math.sin(a)], locy: [0, 1, 0] })
```

`locx` คือแกน x ของโหนดเองเป็นเวกเตอร์ในแกนรวม และ `locy` คือแกน y ซึ่งคงเป็น `[0, 1, 0]` ในแอป EduBeam มุมนี้คือ *มุมระบบพิกัดท้องถิ่นของโหนด* เท่ากับ 30°

หลัง `solve()` B ดันในทิศตั้งฉากกับพื้นเอียง และจุดรองรับแบบหมุดที่ A รับองค์ประกอบแนวนอน:

```ts
b.getReactions(lc).values // [-41569]: N ตามแกน z ของ B เอง, 36 kN / cos 30°
b.getReactions(lc, true).values // [20785, -36000, 0]: ตาม x, ตาม z, โมเมนต์
```

องค์ประกอบแนวดิ่งยังคงเป็น $qL/2 = 36$ kN ส่วนองค์ประกอบแนวนอน $36 \tan 30° = 20.8$ kN ดึงคานจากทั้งสองปลาย โมเมนต์ไม่เปลี่ยน

บนโหนดที่หมุนแกน การกระจัดและแรงปฏิกิริยาอยู่ในแกนของโหนดเอง เว้นแต่จะส่ง `true` เพื่อขอค่าในแกนรวม ส่วนแรงกระทำที่โหนดนั้นอยู่ในแกนรวม เว้นแต่จะระบุเป็นอย่างอื่น ดู [แรงกระทำที่โหนด](/th/solver/loads#nodal-loads) เรียก `node.updateLcs()` โดยไม่มีอาร์กิวเมนต์เพื่อหมุนแกนกลับ

## แก้ไขโหนด {#change-a-node}

โหนดเป็นออบเจกต์ธรรมดา เปลี่ยน `node.coords` เพื่อย้ายโหนด หรือแทนที่ `node.bcs` ซึ่งเป็น `Set<DofID>` เพื่อเปลี่ยนจุดรองรับ

```ts
domain.getNode('B').coords = [8, 0, 0] // ช่วงยาวขึ้น: แค่ solve() ก็พอ
domain.getNode('A').bcs = new Set(fixed) // จุดรองรับใหม่: กำหนดหมายเลขใหม่ก่อน
solver.codeNumberGenerated = false
solver.solve()
```

การเปลี่ยนจุดรองรับ หรือการเพิ่มและลบโหนด ทำให้ชุดสมการเปลี่ยน ถ้าไม่ตั้ง `codeNumberGenerated = false` ตัวคำนวณจะ **ใช้จุดรองรับเดิมต่อไปโดยไม่แจ้งเตือน** หัวข้อ [คำนวณใหม่หลังแก้ไขโมเดล](/th/solver/solving#solving-again-after-a-change) บอกว่าการแก้ไขแบบใดต้องทำขั้นตอนนี้
