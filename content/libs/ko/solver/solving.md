# 해석 {#solving}

```ts
solver.solve()
```

`solve()`는 방정식에 번호를 매기고, 전체 강성 행렬과 모든 하중조건의 하중 벡터를 조립한 다음, 변위와 반력을 구합니다. 그 뒤에는 모든 [결과](/ko/solver/results)를 읽을 수 있고, 그 전에 결과를 읽으면 `TypeError`가 발생합니다. 이 단계는 이론 매뉴얼의 [EduBeam의 해석 과정](/ko/elements/analysis)에서 설명하는 단계와 같습니다.

선형 모델에 대해서는 해가 정확합니다. 각 부재를 따라가는 변형 형상과 부재력은 Timoshenko 보의 닫힌 해에서 나오므로, 요소를 더 잘게 나눌 필요가 없고 다이어그램을 정확하게 얻으려고 부재를 쪼갤 필요도 없습니다.

0.3.1부터 `solve()`는 콘솔에 아무것도 출력하지 않습니다. 0.3.0은 호출할 때마다 `Solution took 9 [ms]` 같은 줄을 출력했습니다.

## 변경 후 다시 풀기 {#solving-again-after-a-change}

모델의 숫자만 바꿨다면 `solve()`를 한 번 더 호출하면 됩니다. 방정식의 구성이 바뀌었다면 그 전에 한 줄이 더 필요합니다.

```ts
domain.createNode('C', [10, 0, 0], [DofID.Dz])
domain.createBeam2D(2, ['B', 'C'], 1, 1)
solver.codeNumberGenerated = false // 자유도가 바뀌었으므로 번호를 다시 매김
solver.solve()
```

| 변경 | 다음 할 일 |
| --- | --- |
| 하중 값, 하중 추가나 삭제 | `solve()` |
| 절점 좌표, 재료, 단면, 힌지 | `solve()` |
| 절점이나 부재 추가 | `codeNumberGenerated = false` 후 `solve()` |
| 절점이나 부재 삭제: `domain.nodes.delete(label)`, `domain.elements.delete(label)` | `codeNumberGenerated = false` 후 `solve()` |
| 절점의 지점 `node.bcs` 변경 | `codeNumberGenerated = false` 후 `solve()` |

절점을 추가하고 이 설정을 잊으면 `solve()`가 `TypeError`를 던집니다. 지점을 바꾸고 잊으면 **아무 경고 없이** 이전 지점 조건으로 풉니다. 확실하지 않으면 그냥 `false`로 설정하세요. 번호 매기기에는 시간이 거의 들지 않습니다. 부재를 삭제할 때는 그 부재의 하중도 `lc.elementLoadList`에서 지워야 합니다. 그렇지 않으면 `solve()`가 없는 부재에 대해 `RangeError`를 던집니다.

매개변수 연구처럼 한 모델의 여러 변형을 풀 때는 변형마다 새 솔버를 만드는 편이 더 간단하고 속도도 같습니다. [영향선 예제](/ko/solver/scripts#an-influence-line-as-csv)를 참고하세요.

## 해석이 실패할 때 {#when-solving-fails}

변형 없이 움직일 수 있는 구조물, 즉 메커니즘은 강성 행렬이 특이 행렬입니다. `solve()`가 이를 알아채고 오류를 던질 때도 있습니다.

```text
Error: Linear system cannot be solved since matrix is singular
```

하지만 알아채지 못할 때가 많습니다. 반올림 오차 때문에 행렬이 풀 수 있는 것처럼 보여서, $10^{12}$ m 같은 변위가 나오거나, 자유롭게 미끄러질 수 있는 구조물인데도 그럴듯해 보이는 숫자가 나옵니다. 예를 들어 롤러 지점 두 개 위의 보는 옆으로 미는 힘이 없는 한 아무 문제 없이 풀립니다. 그러므로 지점은 직접 확인하고, 변위가 엄청나게 크면 메커니즘의 신호로 보세요.

흔한 원인은 다음과 같습니다.

- 지점이 너무 적음. 예: 롤러 지점 두 개 위의 보
- 구조물을 붙잡을 수 없는 지점 배치: 반력 방향이 모두 평행하거나, 모두 한 점을 향함
- 힌지가 하나 더 많음. 예: 힌지 세 개가 일직선 위에 있음
- 모든 부재 끝이 힌지인 절점에 가한 모멘트

오류 메시지는 문제가 어디에 있는지 알려 주지 않습니다. EduBeam 앱은 풀기 전에 메커니즘을 검사하고, 그 움직임을 찾아 애니메이션으로 보여 줍니다. 같은 모델을 앱에서 만들어 보는 것이 원인을 찾는 가장 빠른 방법일 때가 많습니다. 흔한 원인은 [문제 해결](/ko/reference/troubleshooting)에 정리되어 있습니다.

절점, 재료, 단면이 없으면 그 이름을 담은 `RangeError`가 발생합니다. 단면 매개변수가 빠진 경우에는 오류가 전혀 나지 않고 모든 결과가 `NaN`이 됩니다. [재료 및 단면](/ko/solver/materials-sections#cross-section)을 참고하세요.

## 모델 크기 {#model-size}

솔버는 밀집 행렬을 쓰며, 수업에서 다루는 크기의 모델을 위해 만들어졌습니다. 노트북의 Node에서 부재를 일직선으로 이은 모델을 푸는 데 걸리는 시간은 대략 다음과 같습니다.

| 부재 수 | 자유도 수 | 시간 |
| --- | --- | --- |
| 50 | 150 | 0.1초 |
| 100 | 300 | 0.2초 |
| 200 | 600 | 1초 |
| 400 | 1200 | 10초 |

모델 크기가 두 배가 될 때마다 시간은 6–9배 늘어납니다.

구조역학 과목의 연습 문제, 라멘, 트러스는 모두 넉넉히 풀 수 있습니다. 부재가 수천 개인 모델을 위한 솔버는 아닙니다.

## 다른 해석은 지원하지 않음 {#no-other-analyses}

이 버전은 선형 정적 해석만 풉니다. 소스 코드에는 고유진동수를 구하는 고유치 솔버가 있지만, 배포되는 패키지에는 포함되어 있지 않습니다. `EigenValueDynamicSolver`는 `@edubeam/fem`에서 가져올 수 없습니다.
