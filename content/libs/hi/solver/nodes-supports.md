# नोड और सपोर्ट {#nodes-and-supports}

नोड वे बिंदु हैं जिन पर सदस्य जुड़ते हैं। सपोर्ट कोई अलग वस्तु नहीं है: यह उन स्वातंत्र्य-कोटियों (DOF) की सूची है जिन्हें नोड रोके रखता है। इस पृष्ठ के कोड-अंश [शुरुआत](/hi/solver/getting-started) जैसे किसी प्रोग्राम के हिस्से हैं और उसी के `solver`, `domain` और `lc` का उपयोग करते हैं।

## नोड बनाना {#create-a-node}

```ts
domain.createNode(label, [x, y, z], bcs)
```

| Argument | प्रकार | अर्थ |
| --- | --- | --- |
| `label` | `string \| number` | नोड का नाम, स्ट्रिंग के रूप में संग्रहीत: `1` और `'1'` एक ही नोड हैं। |
| `coords` | `number[]` | `[x, y, z]` मीटर में, `y = 0` के साथ। z नीचे की ओर है। |
| `bcs` | `DofID[]` | वे DOF जिन्हें सपोर्ट रोकता है। मुक्त नोड के लिए इसे छोड़ दें। |

यह `Node` लौटाता है; `domain.getNode(label)` उसे फिर से ढूँढ़ देता है। पहले से उपयोग में आया लेबल पुराने नोड को बदल देता है।

```ts
import { DofID } from '@edubeam/fem'

const fixed = [DofID.Dx, DofID.Dz, DofID.Ry]
domain.createNode('A', [0, 0, 0], fixed)
domain.createNode('B', [0, 0, -4]) // मुक्त: 4 m ऊँचे स्तंभ का शीर्ष
```

## सपोर्ट {#supports}

EduBeam ऐप का हर सपोर्ट रोकी गई DOF का एक समूह है:

| सपोर्ट | `bcs` | क्या रोकता है |
| --- | --- | --- |
| फिक्स्ड | `[DofID.Dx, DofID.Dz, DofID.Ry]` | सब कुछ |
| पिन | `[DofID.Dx, DofID.Dz]` | दोनों विस्थापन, घूमने के लिए मुक्त |
| रोलर | `[DofID.Dz]` | ऊर्ध्वाधर विस्थापन, x के अनुदिश लुढ़कता है |
| ऊर्ध्वाधर रोलर | `[DofID.Dx]` | क्षैतिज विस्थापन, z के अनुदिश लुढ़कता है |
| स्लाइडर | `[DofID.Dz, DofID.Ry]` | ऊर्ध्वाधर विस्थापन और घूर्णन, x के अनुदिश सरकता है |
| ऊर्ध्वाधर स्लाइडर | `[DofID.Dx, DofID.Ry]` | क्षैतिज विस्थापन और घूर्णन, z के अनुदिश सरकता है |
| केवल घूर्णन अवरुद्ध | `[DofID.Ry]` | घूर्णन |

आप इन्हें जिस क्रम में लिखते हैं, [प्रतिक्रियाएँ](/hi/solver/results#reactions) उसी क्रम में लौटती हैं। संरचना को कम से कम तीन रोकी गई DOF चाहिए, और वे ऐसी हों कि संरचना यंत्र (mechanism) की तरह हिल न सके: देखें [जब हल विफल हो](/hi/solver/solving#when-solving-fails)।

रोकी गई DOF को किसी दी गई मात्रा से खिसकाया भी जा सकता है, यानी सपोर्ट का धँसाव (support settlement): देखें [निर्धारित विस्थापन](/hi/solver/temperature-settlements#prescribed-displacements)।

## झुके सपोर्ट {#inclined-supports}

ढलान पर रखा रोलर नोड को ऊर्ध्वाधर दिशा में नहीं, बल्कि ढलान के लंबवत रोकता है। `updateLcs` से नोड के अक्ष घुमाएँ; तब उसके `bcs` घुमाए गए अक्षों के सापेक्ष माने जाते हैं। शुरुआत वाले प्रोग्राम में B को इस तरह बनाएँ:

```ts
const b = domain.createNode('B', [6, 0, 0], [DofID.Dz]) // अपना z रोकता है
const a = (30 * Math.PI) / 180 // 30°, x से z की ओर: स्क्रीन पर दक्षिणावर्त
b.updateLcs({ locx: [Math.cos(a), 0, Math.sin(a)], locy: [0, 1, 0] })
```

`locx` नोड का अपना x अक्ष है, वैश्विक अक्षों में सदिश के रूप में, और `locy` उसका y अक्ष, जो `[0, 1, 0]` ही रहता है। EduBeam ऐप में यही कोण नोड का *नोडल LCS कोण* है, 30°।

`solve()` के बाद B ढलान के लंबवत धकेलता है, और A का पिन क्षैतिज घटक लेता है:

```ts
b.getReactions(lc).values // [-41569]: B के अपने z के अनुदिश N, 36 kN / cos 30°
b.getReactions(lc, true).values // [20785, -36000, 0]: x के अनुदिश, z के अनुदिश, आघूर्ण
```

::model-figure{caption="30° घुमाया गया रोलर: उसकी प्रतिक्रिया ढलान के लंबवत है और बीम में तनाव है।"}
---

supports: { A: pin, B: roller }
angles: { B: 30 }

  - { member: 1, qz: 12 }

::

ऊर्ध्वाधर घटक अब भी $qL/2 = 36$ kN है; क्षैतिज घटक, $36 \tan 30° = 20.8$ kN, बीम को दोनों सिरों से खींचता है। आघूर्ण नहीं बदलता।

घुमाए गए नोड पर विस्थापन और प्रतिक्रियाएँ नोड के अपने अक्षों में होती हैं, जब तक आप वैश्विक अक्षों के लिए `true` न दें। उस पर लगे नोडल भार वैश्विक होते हैं, जब तक आप कुछ और न कहें: देखें [नोडल भार](/hi/solver/loads#nodal-loads)। बिना argument के `node.updateLcs()` अक्षों को वापस मूल स्थिति में ले आता है।

## नोड बदलना {#change-a-node}

नोड एक साधारण object है: उसे खिसकाने के लिए `node.coords` बदलें, या सपोर्ट बदलने के लिए `node.bcs` बदलें, जो एक `Set<DofID>` है।

```ts
domain.getNode('B').coords = [8, 0, 0] // लंबा स्पैन: solve() काफ़ी है
domain.getNode('A').bcs = new Set(fixed) // नया सपोर्ट: पहले फिर से क्रमांकन करें
solver.codeNumberGenerated = false
solver.solve()
```

सपोर्ट बदलने, या नोड जोड़ने और हटाने से समीकरण बदल जाते हैं: `codeNumberGenerated = false` के बिना सॉल्वर **चुपचाप पुराने सपोर्ट ही रखता है**। [बदलाव के बाद दोबारा हल करना](/hi/solver/solving#solving-again-after-a-change) बताता है कि किन बदलावों में इसकी ज़रूरत होती है।
