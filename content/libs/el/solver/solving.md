# Επίλυση {#solving}

```ts
solver.solve()
```

Η `solve()` αριθμεί τις εξισώσεις, συναρμολογεί το καθολικό μητρώο στιβαρότητας και τα διανύσματα φορτίων κάθε περίπτωσης φόρτισης και υπολογίζει τις μετακινήσεις και τις αντιδράσεις. Μετά από αυτήν μπορεί να διαβαστεί κάθε [αποτέλεσμα](/el/solver/results)· πριν από αυτήν, η ανάγνωση προκαλεί `TypeError`. Τα βήματα είναι αυτά της σελίδας [Πώς επιλύει το EduBeam](/el/elements/analysis) του θεωρητικού εγχειριδίου.

Η λύση του γραμμικού μοντέλου είναι ακριβής: η ελαστική γραμμή και τα εντατικά μεγέθη κατά μήκος κάθε μέλους προκύπτουν από αναλυτικές λύσεις της δοκού Timoshenko, οπότε δεν υπάρχει πλέγμα για πύκνωση ούτε χρειάζεται να χωρίσετε μέλη για ακριβή διαγράμματα.

Από την έκδοση 0.3.1 η `solve()` δεν γράφει τίποτε στην κονσόλα· η 0.3.0 εμφάνιζε σε κάθε κλήση μια γραμμή όπως `Solution took 9 [ms]`.

## Νέα επίλυση μετά από αλλαγή {#solving-again-after-a-change}

Αν αλλάζουν μόνο αριθμοί στο μοντέλο, αρκεί μια νέα `solve()`. Αν αλλάζει το ποιες εξισώσεις υπάρχουν, χρειάζεται πρώτα μία γραμμή ακόμη:

```ts
domain.createNode('C', [10, 0, 0], [DofID.Dz])
domain.createBeam2D(2, ['B', 'C'], 1, 1)
solver.codeNumberGenerated = false // άλλαξαν οι βαθμοί ελευθερίας: νέα αρίθμηση
solver.solve()
```

| Αλλαγή | Έπειτα |
| --- | --- |
| Τιμές φορτίων, νέα ή αφαιρεμένα φορτία | `solve()` |
| Συντεταγμένες κόμβων, υλικά, διατομές, αρθρώσεις | `solve()` |
| Προσθήκη κόμβων ή μελών | `codeNumberGenerated = false`, μετά `solve()` |
| Αφαίρεση κόμβων ή μελών: `domain.nodes.delete(label)`, `domain.elements.delete(label)` | `codeNumberGenerated = false`, μετά `solve()` |
| Αλλαγή των στηρίξεων ενός κόμβου, `node.bcs` | `codeNumberGenerated = false`, μετά `solve()` |

Αν το ξεχάσετε μετά την προσθήκη κόμβου, η `solve()` προκαλεί `TypeError`. Αν το ξεχάσετε μετά την αλλαγή στήριξης, επιλύει **σιωπηλά** με τις παλιές στηρίξεις. Αν έχετε αμφιβολία, μηδενίστε τη σημαία: η αρίθμηση δεν κοστίζει σχεδόν τίποτε. Όταν αφαιρείτε ένα μέλος, αφαιρέστε και τα φορτία του από το `lc.elementLoadList`, αλλιώς η `solve()` προκαλεί `RangeError` για το μέλος που λείπει.

Για πολλές παραλλαγές ενός μοντέλου, όπως σε μια παραμετρική μελέτη, ένας νέος επιλυτής για καθεμία είναι απλούστερος και εξίσου γρήγορος: δείτε το [παράδειγμα γραμμής επιρροής](/el/solver/scripts#an-influence-line-as-csv).

## Όταν η επίλυση αποτυγχάνει {#when-solving-fails}

Ένας φορέας που μπορεί να κινηθεί χωρίς να παραμορφωθεί, δηλαδή ένας μηχανισμός, έχει ιδιάζον μητρώο στιβαρότητας. Μερικές φορές η `solve()` το αντιλαμβάνεται και προκαλεί εξαίρεση:

```text
Error: Linear system cannot be solved since matrix is singular
```

Συχνά όμως όχι: τα σφάλματα στρογγύλευσης κάνουν το μητρώο να φαίνεται επιλύσιμο και παίρνετε μετακινήσεις της τάξης των $10^{12}$ m ή αριθμούς που φαίνονται εύλογοι για έναν φορέα που μπορεί να ολισθήσει ελεύθερα. Μια δοκός σε δύο κυλίσεις, για παράδειγμα, επιλύεται χωρίς κανένα πρόβλημα όσο τίποτε δεν την ωθεί πλευρικά. Γι' αυτό ελέγξτε μόνοι σας τις στηρίξεις και θεωρήστε τις τεράστιες μετακινήσεις ένδειξη μηχανισμού.

Συνήθεις αιτίες:

- πολύ λίγες στηρίξεις, όπως δοκός σε δύο κυλίσεις·
- στηρίξεις που δεν μπορούν να συγκρατήσουν τον φορέα: όλες παράλληλες ή όλες με διευθύνσεις που διέρχονται από ένα σημείο·
- μία άρθρωση παραπάνω, όπως τρεις στη σειρά·
- ροπή που ασκείται σε κόμβο όπου όλα τα άκρα μελών είναι αρθρωτά.

Το μήνυμα δεν λέει πού βρίσκεται το πρόβλημα. Η εφαρμογή EduBeam ελέγχει για μηχανισμούς πριν από την επίλυση και εντοπίζει και δείχνει κινούμενη την κινηματική αλυσίδα· η κατασκευή του ίδιου μοντέλου εκεί είναι συχνά ο γρηγορότερος τρόπος να τη δείτε. Η σελίδα [Επίλυση προβλημάτων](/el/reference/troubleshooting) αναφέρει τις συνήθεις αιτίες.

Αν λείπει κόμβος, υλικό ή διατομή, προκαλείται `RangeError` με το όνομά του. Οι παράμετροι διατομής που λείπουν δεν προκαλούν κανένα σφάλμα: κάθε αποτέλεσμα είναι `NaN`. Δείτε [Υλικά και διατομές](/el/solver/materials-sections#cross-section).

## Μέγεθος μοντέλου {#model-size}

Ο επιλυτής χρησιμοποιεί πυκνά μητρώα, φτιαγμένα για μοντέλα διδακτικού μεγέθους. Σε φορητό υπολογιστή, στο Node, μια ευθεία σειρά μελών επιλύεται περίπου σε:

| Μέλη | Βαθμοί ελευθερίας | Χρόνος |
| --- | --- | --- |
| 50 | 150 | 0,1 s |
| 100 | 300 | 0,2 s |
| 200 | 600 | 1 s |
| 400 | 1200 | 10 s |

Κάθε διπλασιασμός του μοντέλου κοστίζει έξι έως εννέα φορές περισσότερο χρόνο.

Κάθε άσκηση, πλαίσιο και δικτύωμα ενός μαθήματος στατικής χωρά άνετα. Δεν προορίζεται για μοντέλα χιλιάδων μελών.

## Καμία άλλη ανάλυση {#no-other-analyses}

Αυτή η έκδοση εκτελεί μόνο γραμμική στατική ανάλυση. Ο πηγαίος κώδικας περιέχει επιλυτή ιδιοτιμών για ιδιοσυχνότητες, αλλά δεν είναι μέρος του δημοσιευμένου πακέτου: ο `EigenValueDynamicSolver` δεν μπορεί να εισαχθεί από το `@edubeam/fem`.
