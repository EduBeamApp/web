# Расчёт {#solving}

```ts
solver.solve()
```

`solve()` нумерует уравнения, собирает глобальную матрицу жёсткости и векторы нагрузок всех случаев нагружения и находит перемещения и реакции. После этого можно читать любые [результаты](/ru/solver/results), а до него любое чтение результатов выбрасывает `TypeError`. Шаги те же, что на странице [Как EduBeam рассчитывает модель](/ru/elements/analysis) теоретического раздела.

Для линейной модели решение точное: деформированная схема и внутренние усилия вдоль каждого стержня получаются из аналитического решения для балки Тимошенко, поэтому нет сетки, которую нужно сгущать, и не нужно разбивать стержни ради точных эпюр.

Начиная с версии 0.3.1 `solve()` ничего не выводит в консоль; версия 0.3.0 при каждом вызове печатала строку вроде `Solution took 9 [ms]`.

## Повторный расчёт после изменений {#solving-again-after-a-change}

Если в модели изменились только числа, достаточно ещё раз вызвать `solve()`. Если изменился сам набор уравнений, перед этим нужна ещё одна строка:

```ts
domain.createNode('C', [10, 0, 0], [DofID.Dz])
domain.createBeam2D(2, ['B', 'C'], 1, 1)
solver.codeNumberGenerated = false // степени свободы изменились: нумеруем заново
solver.solve()
```

| Изменение | Что делать |
| --- | --- |
| Значения нагрузок, новые или удалённые нагрузки | `solve()` |
| Координаты узлов, материалы, сечения, шарниры | `solve()` |
| Добавление узлов или стержней | `codeNumberGenerated = false`, затем `solve()` |
| Удаление узлов или стержней: `domain.nodes.delete(label)`, `domain.elements.delete(label)` | `codeNumberGenerated = false`, затем `solve()` |
| Изменение опор узла, `node.bcs` | `codeNumberGenerated = false`, затем `solve()` |

Если забыть об этом после добавления узла, `solve()` выбросит `TypeError`. Если забыть после изменения опоры, `solve()` **молча** рассчитает модель со старыми опорами. Если сомневаетесь, сбрасывайте флаг: нумерация почти ничего не стоит. Удаляя стержень, удалите и его нагрузки из `lc.elementLoadList`, иначе `solve()` выбросит `RangeError` из-за отсутствующего стержня.

Для множества вариантов одной модели, например в параметрическом исследовании, проще и не медленнее создавать для каждого варианта новый решатель: см. [пример с линией влияния](/ru/solver/scripts#an-influence-line-as-csv).

## Если расчёт не удался {#when-solving-fails}

У конструкции, которая может двигаться без деформации, т. е. у механизма, матрица жёсткости вырождена. Иногда `solve()` это замечает и выбрасывает исключение:

```text
Error: Linear system cannot be solved since matrix is singular
```

Часто же нет: из-за ошибок округления матрица выглядит разрешимой, и получаются перемещения порядка $10^{12}$ м или правдоподобные на вид числа для конструкции, которая может свободно скользить. Например, балка на двух шарнирно-подвижных опорах рассчитывается без возражений, пока ничто не толкает её вбок. Поэтому проверяйте опоры сами и считайте огромные перемещения признаком механизма.

Типичные причины:

- слишком мало опор, например балка на двух шарнирно-подвижных опорах;
- опоры не могут удержать конструкцию: все они параллельны или все направлены в одну точку;
- лишний шарнир, например три шарнира на одной прямой;
- момент, приложенный к узлу, в котором все концы стержней шарнирные.

Из сообщения не видно, где проблема. Приложение EduBeam перед расчётом проверяет модель на механизм, находит его и анимирует движение; построить ту же модель там — часто самый быстрый способ его увидеть. Обычные причины перечислены на странице [Устранение неполадок](/ru/reference/troubleshooting).

Отсутствующий узел, материал или сечение вызывает `RangeError` с его именем. Отсутствующие параметры сечения вообще не вызывают ошибки: все результаты будут `NaN`. См. [Материалы и сечения](/ru/solver/materials-sections#cross-section).

## Размер модели {#model-size}

Решатель использует плотные матрицы и рассчитан на учебные модели. На ноутбуке в Node цепочка стержней на одной прямой рассчитывается примерно за:

| Стержней | Степеней свободы | Время |
| --- | --- | --- |
| 50 | 150 | 0,1 с |
| 100 | 300 | 0,2 с |
| 200 | 600 | 1 с |
| 400 | 1200 | 10 с |

Каждое удвоение модели увеличивает время в 6–9 раз.

Любая задача, рама или ферма из курса строительной механики помещается с большим запасом. Для моделей из тысяч стержней решатель не предназначен.

## Других видов расчёта нет {#no-other-analyses}

Эта версия выполняет только линейный статический расчёт. В исходном коде есть решатель для собственных частот колебаний (задача на собственные значения), но в опубликованный пакет он не входит: `EigenValueDynamicSolver` нельзя импортировать из `@edubeam/fem`.
