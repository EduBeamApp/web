# 解析 {#solving}

```ts
solver.solve()
```

`solve()` は方程式に番号を付け、全体剛性マトリクスとすべての荷重ケースの荷重ベクトルを組み立て、変位と反力を求めます。その後は、どの[結果](/ja/solver/results)でも読み出せます。解く前に読み出そうとすると `TypeError` が投げられます。手順は、理論マニュアルの[EduBeam がモデルを解く仕組み](/ja/elements/analysis)と同じです。

線形モデルに対して、解は厳密です。各部材の変形と断面力はティモシェンコ梁の解析解から求めるので、細かくすべきメッシュはなく、正確な断面力図を得るために部材を分割する必要もありません。

`solve()` は、0.3.1 以降はコンソールに何も出力しません。0.3.0 では、呼び出すたびに `Solution took 9 [ms]` のような行を出力していました。

## 変更後の再計算 {#solving-again-after-a-change}

モデルの数値を変えただけなら、もう一度 `solve()` を呼ぶだけで済みます。方程式の構成そのものが変わる場合は、その前に 1 行追加が必要です。

```ts
domain.createNode('C', [10, 0, 0], [DofID.Dz])
domain.createBeam2D(2, ['B', 'C'], 1, 1)
solver.codeNumberGenerated = false // 自由度が変わったので番号を付け直す
solver.solve()
```

| 変更 | その後の操作 |
| --- | --- |
| 荷重の値、荷重の追加・削除 | `solve()` |
| 節点座標、材料、断面、ヒンジ | `solve()` |
| 節点や部材の追加 | `codeNumberGenerated = false` の後に `solve()` |
| 節点や部材の削除：`domain.nodes.delete(label)`、`domain.elements.delete(label)` | `codeNumberGenerated = false` の後に `solve()` |
| 節点の支点（`node.bcs`）の変更 | `codeNumberGenerated = false` の後に `solve()` |

節点を追加した後にこれを忘れると、`solve()` は `TypeError` を投げます。支点を変更した後に忘れると、**何も知らせずに**古い支点のまま解きます。迷ったらリセットしてください。番号付けの計算コストはほとんどありません。部材を削除するときは、その部材の荷重も `lc.elementLoadList` から削除してください。そうしないと、`solve()` は存在しない部材について `RangeError` を投げます。

パラメータースタディのように 1 つのモデルの変種を多数解く場合は、そのたびに新しいソルバーを作るほうが簡単で、速さも変わりません。[影響線のプログラム例](/ja/solver/scripts#an-influence-line-as-csv)を参照してください。

## 解析に失敗するとき {#when-solving-fails}

変形せずに動ける構造物、つまり不安定構造（機構）の剛性マトリクスは特異です。`solve()` がそれを検出して、例外を投げることもあります。

```text
Error: Linear system cannot be solved since matrix is singular
```

しかし多くの場合は検出されません。丸め誤差のために行列が解けるように見えてしまい、$10^{12}$ m という変位や、自由に滑る構造物なのにもっともらしく見える数値が返ってきます。たとえば 2 つのローラー支点に載った梁は、横から押す力がない限り、何の警告もなく解けてしまいます。ですから支点は自分で確認し、異常に大きな変位は不安定構造のサインと考えてください。

典型的な原因：

- 支点が足りない（2 つのローラー支点に載った梁など）
- 支点が構造物を支えられない配置になっている（すべて平行、またはすべて 1 点を向いている）
- ヒンジが 1 つ多すぎる（3 つ並んでいるなど）
- すべての部材端がヒンジになっている節点に、モーメントが作用している

エラーメッセージは、問題がどこにあるかを示しません。EduBeam アプリは解く前に不安定構造かどうかをチェックし、その動きを見つけてアニメーションで表示します。同じモデルをアプリで作ってみるのが、原因を見つけるいちばんの近道であることも少なくありません。よくある原因は[トラブルシューティング](/ja/reference/troubleshooting)にまとめてあります。

節点、材料、断面が見つからない場合は、その名前を示す `RangeError` が投げられます。断面のパラメーターが足りない場合は例外がまったく出ず、すべての結果が `NaN` になります。[材料と断面](/ja/solver/materials-sections#cross-section)を参照してください。

## モデルの規模 {#model-size}

ソルバーは密行列を使っていて、授業で扱う規模のモデル向けに作られています。ノートパソコンの Node で、部材を一直線に並べたモデルを解く時間はおよそ次のとおりです。

| 部材数 | 自由度数 | 時間 |
| --- | --- | --- |
| 50 | 150 | 0.1 s |
| 100 | 300 | 0.2 s |
| 200 | 600 | 1 s |
| 400 | 1200 | 10 s |

モデルの規模が 2 倍になるごとに、計算時間は 6〜9 倍になります。

構造力学の授業で扱う演習問題、ラーメン、トラスなら、どれも余裕で解けます。数千本の部材からなるモデルは想定していません。

## ほかの解析は未対応 {#no-other-analyses}

このバージョンで解けるのは、線形静的解析だけです。ソースコードには固有振動数を求める固有値ソルバーがありますが、公開パッケージには含まれていません。`EigenValueDynamicSolver` は `@edubeam/fem` から import できません。
