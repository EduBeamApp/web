# Вузли та опори {#nodes-and-supports}

Вузли — це точки, які з’єднують стрижні. Опора не є окремим об’єктом: це перелік ступенів вільності, які вузол тримає закріпленими. Фрагменти коду на цій сторінці — частини програми на зразок тієї, що на сторінці [Початок роботи](/uk/solver/getting-started), і використовують її `solver`, `domain` і `lc`.

## Створення вузла {#create-a-node}

```ts
domain.createNode(label, [x, y, z], bcs)
```

| Аргумент | Тип | Зміст |
| --- | --- | --- |
| `label` | `string \| number` | Назва вузла, зберігається як рядок: `1` і `'1'` — це той самий вузол |
| `coords` | `number[]` | `[x, y, z]` у метрах, де `y = 0`. Вісь z напрямлена вниз. |
| `bcs` | `DofID[]` | Ступені вільності, які закріплює опора. Для вільного вузла цей аргумент пропустіть. |

Метод повертає `Node`; `domain.getNode(label)` знайде його знову. Якщо позначка вже зайнята, новий вузол замінить старий.

```ts
import { DofID } from '@edubeam/fem'

const fixed = [DofID.Dx, DofID.Dz, DofID.Ry]
domain.createNode('A', [0, 0, 0], fixed)
domain.createNode('B', [0, 0, -4]) // вільний: верх колони заввишки 4 m
```

## Опори {#supports}

Кожна опора застосунку EduBeam — це набір закріплених ступенів вільності:

| Опора | `bcs` | Що закріплює |
| --- | --- | --- |
| Защемлення | `[DofID.Dx, DofID.Dz, DofID.Ry]` | усе |
| Шарнір | `[DofID.Dx, DofID.Dz]` | обидва переміщення, поворот вільний |
| Рухомий шарнір | `[DofID.Dz]` | вертикальне переміщення; вузол котиться вздовж x |
| Вертикальний рухомий шарнір | `[DofID.Dx]` | горизонтальне переміщення; вузол котиться вздовж z |
| Ковзне защемлення | `[DofID.Dz, DofID.Ry]` | вертикальне переміщення й поворот; вузол ковзає вздовж x |
| Вертикальне ковзне защемлення | `[DofID.Dx, DofID.Ry]` | горизонтальне переміщення й поворот; вузол ковзає вздовж z |
| Лише поворот | `[DofID.Ry]` | поворот |

У тому порядку, у якому ви їх перелічите, повертаються й [реакції](/uk/solver/results#reactions). Конструкції потрібні щонайменше три закріплені ступені вільності, розміщені так, щоб вона не могла рухатися як механізм: див. [Коли розрахунок не вдається](/uk/solver/solving#when-solving-fails).

Закріплений ступінь вільності можна також змістити на задану величину, тобто задати осідання опори: див. [Задані переміщення](/uk/solver/temperature-settlements#prescribed-displacements).

## Похилі опори {#inclined-supports}

Шарнірно-рухома опора на похилій площині закріплює вузол поперек схилу, а не вертикально. Поверніть осі вузла за допомогою `updateLcs`, і його `bcs` відтак стосуватимуться повернутих осей. У програмі зі сторінки «Початок роботи» створіть B ось так:

```ts
const b = domain.createNode('B', [6, 0, 0], [DofID.Dz]) // закріплює власну вісь z
const a = (30 * Math.PI) / 180 // 30°, від x до z: на екрані за годинниковою стрілкою
b.updateLcs({ locx: [Math.cos(a), 0, Math.sin(a)], locy: [0, 1, 0] })
```

`locx` — це власна вісь x вузла як вектор у глобальних осях, а `locy` — його вісь y, яка залишається `[0, 1, 0]`. У застосунку EduBeam той самий кут задають як *Кут локальної системи координат* вузла, 30°.

Після `solve()` опора B тисне поперек схилу, а шарнірно-нерухома опора в A сприймає горизонтальну складову:

```ts
b.getReactions(lc).values // [-41569]: N уздовж власної осі z вузла B, 36 kN / cos 30°
b.getReactions(lc, true).values // [20785, -36000, 0]: уздовж x, уздовж z, момент
```

Вертикальна складова, як і раніше, дорівнює $qL/2 = 36$ kN; горизонтальна, $36 \tan 30° = 20{,}8$ kN, розтягує балку з обох кінців. Момент не змінюється.

У повернутому вузлі переміщення й реакції подаються у власних осях вузла, якщо ви не передасте `true`, щоб отримати їх у глобальних. Вузлові навантаження на нього задаються в глобальних осях, якщо ви не вкажете інакше: див. [Вузлові навантаження](/uk/solver/loads#nodal-loads). `node.updateLcs()` без аргументу повертає осі у вихідне положення.

## Зміна вузла {#change-a-node}

Вузол — звичайний об’єкт: змініть `node.coords`, щоб перемістити його, або замініть `node.bcs` (типу `Set<DofID>`), щоб змінити опору.

```ts
domain.getNode('B').coords = [8, 0, 0] // довший проліт: досить solve()
domain.getNode('A').bcs = new Set(fixed) // нова опора: спершу перенумеруйте
solver.codeNumberGenerated = false
solver.solve()
```

Зміна опор, додавання й вилучення вузлів змінюють систему рівнянь: без `codeNumberGenerated = false` розв’язувач **мовчки зберігає старі опори**. На сторінці [Повторний розрахунок після зміни](/uk/solver/solving#solving-again-after-a-change) перелічено, яких змін це стосується.
