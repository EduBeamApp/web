# Початок роботи {#getting-started}

@edubeam/fem — це розв’язувач методу скінченних елементів, на якому працює [EduBeam]{.edubeam}: кожну епюру, реакцію і прогин, які показує застосунок, обчислено саме ним. Ним можна розраховувати плоскі балки, рами й ферми з власного коду, у браузері або в Node: генерувати вправи разом із відповідями, перевіряти домашні завдання, виконувати параметричні дослідження або зробити його розрахунковим ядром вебсторінки.

::div{.actions}
[Розрахуйте першу балку](#a-simply-supported-beam) [Перегляньте приклади програм](/uk/solver/beams)
::

Бібліотеку написано на TypeScript, вона містить власні типи і є вільним програмним забезпеченням за ліцензією GPL-3.0. Її створив Bořek Patzák, а розвивають він і Jan Voříšek разом з іншими учасниками.

## Встановлення {#install}

```bash
npm install @edubeam/fem
```

Вона працює з `import` і `require`, у браузері та в Node 18 і новіших версіях, і має одну залежність — [mathjs](https://mathjs.org). До версії 0.3.0 її встановлювали з GitHub під назвою `ts-fem`: якщо ви користувалися нею так, замініть імпорти на `@edubeam/fem`. Більше нічого не змінилося.

Щоб випробувати приклад нижче в порожній теці, зробіть із неї проєкт, який використовує `import`, і встановіть пакет:

```bash
npm init -y
npm pkg set type=module
npm install @edubeam/fem
```

Без `"type": "module"` у `package.json` приклад теж запуститься, але Node спершу виведе попередження.

## Перша балка {#a-simply-supported-beam}

Сталева балка IPE 200 прольотом 6 m на шарнірно-нерухомій і шарнірно-рухомій опорах під навантаженням 12 kN/m:

```ts [beam.ts]
import { DofID, LinearStaticSolver } from '@edubeam/fem'

const solver = new LinearStaticSolver()
const { domain } = solver

// Скрізь одиниці СІ: m, N, Pa. Сталь і IPE 200.
domain.createMaterial('steel', { e: 210e9, g: 81e9 })
domain.createCrossSection('IPE200', { a: 28.5e-4, iy: 1943e-8, k: 5 / 6 })

// Вузли в точках [x, y, z] у метрах і ступені вільності, які закріплює їхня опора
domain.createNode('A', [0, 0, 0], [DofID.Dx, DofID.Dz]) // шарнірно-нерухома опора
domain.createNode('B', [6, 0, 0], [DofID.Dz]) // шарнірно-рухома опора
const beam = domain.createBeam2D(1, ['A', 'B'], 'steel', 'IPE200')

// 12 kN/m уздовж локальної осі z стрижня: на балці, заданій зліва направо, — донизу
const lc = solver.loadCases[0]
lc.createBeamElementUniformEdgeLoad(1, [0, 12e3], true)

solver.solve()

console.log(beam.computeBendingMomentAt(lc, 3)) // N·m посередині прольоту
console.log(beam.computeShearForceAt(lc, 0)) // N у вузлі A
console.log(beam.computeLocalDefl(lc, 2).w[1]) // m посередині прольоту
```

Збережіть код у файл `beam.ts` і запустіть `node beam.ts`: Node 22.18 і новіші версії виконують TypeScript без перетворення. У файлі немає анотацій типів, тож у старішому Node досить зберегти його як `beam.mjs`. Програма виведе:

```text [Вивід]
54000
36000
0.04990940552616746
```

Це значення з підручника: $M = qL^2/8 = 54$ kNm і $V = qL/2 = 36$ kN. Ось та сама балка, розрахована тим самим розв’язувачем просто у вашому браузері:

---

Прогин 49,91 mm на 0,28 mm більший, ніж $5qL^4/384EI = 49{,}63$ mm за теорією Ейлера–Бернуллі. Це не помилка: стрижень є балкою Тимошенка, а 0,28 mm — це $qL^2/8kGA$, тобто деформація зсуву цієї балки. Задайте `k` дуже великим, наприклад `1e32`, і різниця зникне: див. [Деформація зсуву](/uk/solver/materials-sections#shear-deformation).

## Що робить цей код {#what-the-code-does}

::div{.steps}
### Створіть розв’язувач {#make-a-solver}

`new LinearStaticSolver()` має порожній `domain`, у якому зберігається модель, і один випадок навантаження, `solver.loadCases[0]`.

### Опишіть модель {#describe-the-model}

Матеріали й перерізи, вузли з опорами, а потім стрижні між вузлами. Кожен об’єкт має позначку (рядок або число), за якою на нього посилається решта моделі. Див. [Вузли та опори](/uk/solver/nodes-supports), [Матеріали та перерізи](/uk/solver/materials-sections) і [Стрижні та шарніри](/uk/solver/members-hinges).

### Навантажте її {#load-it}

Навантаження належать до випадку навантаження: сили у вузлах, навантаження вздовж стрижнів, температура й осідання опор. Див. [Навантаження](/uk/solver/loads).

### Розрахуйте {#solve}

`solver.solve()` збирає і розв’язує систему рівнянь для всіх випадків навантаження. Див. [Розрахунок](/uk/solver/solving).

### Прочитайте результати {#read-the-results}

Внутрішні зусилля в будь-якому місці стрижня, прогини, кінцеві зусилля, переміщення вузлів і реакції. Див. [Читання результатів](/uk/solver/results), а про епюри — [Побудова епюр](/uk/solver/drawing).
::

## Одиниці та знаки коротко {#axes-and-signs}

Задаєте все в одиницях СІ — отримуєте результати теж у СІ. Модель лежить у площині x–z, **вісь z напрямлена вниз**, тож додатне `fz` тисне донизу, а верх колони заввишки 4 m розташований у $z = -4$. Положення на стрижні задають у метрах від його першого вузла. Додатним є момент, що розтягує нижні волокна. Повний перелік — на сторінці [Одиниці та правила знаків](/uk/solver/conventions).

## Шість частих помилок {#pitfalls}

1. **Вісь z напрямлена вниз.** Гравітаційні навантаження додатні, а все, що вище за опори, має від’ємну координату z. Див. [Осі](/uk/solver/conventions#axes).
2. **Напрям стрижня визначає знак M і w.** Задавайте балки зліва направо, а колони знизу вгору, і знаки будуть такі, як у підручнику. Див. [Напрям стрижня](/uk/solver/conventions#member-direction).
3. **Відсутній параметр дає `NaN` або безглуздий результат, а не помилку.** Перерізу потрібні `a`, `iy` і `k`; матеріалу потрібен `e`, а також `g`, якщо `k` не дуже велике. Див. [Матеріали та перерізи](/uk/solver/materials-sections).
4. **Після додавання вузлів чи стрижнів або зміни опор** задайте `solver.codeNumberGenerated = false` перед повторним розрахунком. Див. [Повторний розрахунок після зміни](/uk/solver/solving#solving-again-after-a-change).
5. **Реакції повертаються як матриця mathjs або як масив**, у тому порядку, у якому задано ступені вільності опори. Див. [Реакції](/uk/solver/results#reactions).
6. **Механізм не завжди викликає виняток.** Переміщення порядку $10^{12}$ m означає, що конструкція може вільно рухатися. Див. [Коли розрахунок не вдається](/uk/solver/solving#when-solving-fails).
